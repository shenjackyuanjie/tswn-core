# namer-pf 初始化优化（2026-10-28）

## 范围与方法

本轮在 FFA 非 PGO 优化之后，单独比较 `pp / pd / qp / qd`；不是与尚未优化的 main 比较。
基线为 `c435c8cb`（生产代码与已发布 `de1a5fae` 相同，后续仅报告工具变更）。
两侧使用 Rust 1.99.1、workspace release 的 fat LTO / 单 codegen unit、`no_debug`、默认 mimalloc；没有 PGO、`target-cpu=native` 或额外 RUSTFLAGS。

最终收窄候选 C 的生产改动仅在 `runtime/prepared_init/roster.rs`：**超过四个动态 profile 时按四路分块调用现有交错 RC4 KSA；四个及以下保留原始调用方式。** 不增加 unsafe、不改变随机流，也不改变任何模式的同族排序/升级。

探索候选 B（本地检查点 `f0388a7`）曾同时跳过 `!` 模式的无效同族升级，并对所有大小都使用分块循环。它在整体测量中偏正，但若干多线程病例负向，所以本轮撤回该实现，只保留更小范围的候选 C；下文保留 B 的完整数据，不把 B 的收益冒用为 C 的结果。

## 验证

- debug core：657 通过。
- release `no_debug` core：652 通过；同配置 CLI：91 通过。
- nightly fmt：通过；core/CLI clippy 退出 0（有告警，不是零告警检查）。
- 新增紧凑 profile / 完整构造等价测试：两种 modifier、rq 4 / 6、1–9 与 16 个 profile、正常数字区间和十进制位数边界。
- 原始评分统计差分：14 个输入组 × 4 项 × 三个场数/线程配置（257/1、1001/4、2000/1），共 168 组比较。162 组成功，`group_sizes / total / wins / errors / guard_exhausted` 完全一致；错误计数为零。另六组是两侧一致的原有 panic，详见限制。
- CLI E2E 比较使用 9 位分数输出并逐次核对 stdout；这只表示输出相同，不能代替上面的原始统计差分。

### 采样参考

在真正 8 人 target 组上，双方各完成 100000 场 qp，`group_sizes=[8]`、胜场 63166、errors/guard 均为 0。gprofng 100ms 采样的总 CPU 秒数约 18.9 / 17.7，仅约 189 / 177 个样本。profile 准备是主要热点之一，但 LTO 内联归因和样本量使单个函数百分比不稳定；这两次带采样运行不作为正式提速数字。另有 8 个独立单名的基线采样用于定位初始化热点，不将其冒称为 8 人组。


## 既有边界（本轮不改变行为）

1. 单名 `33554433@U+0002` 的 pp、`33554433@!` 的 qp，在 n=257 / 1001 / 2000 的基线和候选都出现 `runtime remembered summon disappeared` panic。同 clan 回退路径现有测试仅覆盖 n=2，不能保证长运行。本轮没有修补战斗语义；这两个病例从所有指标的正常性能矩阵中显式排除，脚本汇总保留排除清单，未按性能结果筛选。
2. profile 数字名字跨十进制长度时，缓存路径保留首轮 `input_groups` 顺序，而完整重建会按新名字字典序调整。新测试在未修改生产代码的基线上复现相同差异；本轮添加特征测试保留该行为，另在相同缓存布局下验证 KSA 等价。常规几千/一万轮不会从 `PROFILE_START=33554431` 跨到 1e8；足够大的公开调用仍可能触达此边界。
3. 不宣称完成所有 workspace/语言绑定测试；本轮改动集中在初始化，采用上述 core/CLI、构造差分与实际评分差分。未修改武器实现或调整战斗上限。
