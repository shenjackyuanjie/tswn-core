# 可见战斗片段的侧栏快照优化（2026-11-23）

基线为 `86949b50`（交互回合已移除重复就绪校验）。候选只改回放投影：同一帧的玩家顺序预排一次，帧末状态按引用查询；片段前态移入侧栏，片段后态只复制一次。保留精确 HP、护盾更新和新实体进入侧栏的时机，公共回放结构不变。

132 场回放样本（固定 30 个阵容、3 个 Boss 输入，各 4 个 seed）共推进 3,875 回合、输出 3,722 个可见帧，不可见回合约占 3.95%。本轮因此先优化可见片段，未给 Runtime 增加空回合标记或快照缓存。

## 会话 A/B

Windows 10 build 19045、Ryzen 7 5800X、Rust 1.100.0；同机单进程串行配对，首组预热不计，后续五组交替先后顺序。每个版本每组在四种固定输入上分别运行有图标和无图标各 1,000 场，比较 `BattleSession` 从构造到读取终局结果的耗时。只使用 `battle_session` 记录，不计单独的 encoder 记录。统计为每组候选/基线耗时之比的变化率中位数。

| 负载 | 耗时变化 | 候选较快组数 |
| --- | ---: | ---: |
| 全部 | −26.66% | 5/5 |
| 无图标 | −29.77% | 5/5 |
| 有图标 | −25.41% | 5/5 |
| 1v1 | −8.54% | 4/5 |
| 2v2 | −18.99% | 5/5 |
| FFA8 | −28.68% | 5/5 |
| 3v3v3 | −27.80% | 5/5 |

总体五组变化为 −26.66%、−29.07%、−32.14%、−25.65%、−25.35%。这是会话回放耗时，不包含 JSON 序列化，也不代表无回放的胜率吞吐。每组的场数、终局摘要、可见帧与推进回合数一致。另用发布版 CLI 对拍上述 132 场完整 JSONL，共 3,986 行逐字节一致。

## 复测

```powershell
& ./target/replay-ab/release/examples/perf_maintenance.exe --encoder-iters 1 --session-iters 1000 --warmup 10 --input-dir crates/tswn_test/cases/runtime_stress
```

输入与口径见 [perf_maintenance](../../../crates/tswn_core/examples/perf_maintenance.rs)。
