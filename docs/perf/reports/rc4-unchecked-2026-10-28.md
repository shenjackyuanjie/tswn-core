# RC4 unchecked 定向复核（2026-10-28）

## 结论

**不新增生产 `unsafe`，不宣称获得新的 E2E 加速。** 当前最热的 PRGA、普通 KSA 和同长度交错 KSA 本来已经使用原始指针；剩下的 `u8` S-box 索引，编译器已消除边界检查。变量长度交错 KSA 存在可消除的动态密钥检查，但常规 namer-pf 样本不进入该分支，小范围微基准不能证明端到端收益。

本次只新增这份审阅/实验记录与数字摘要，不改 core、武器、编译选项、PGO 或 golden。

## 基线与方式

- 已发布实现：`de1a5fae39b9727115f75db927757a5829fd7f9d`；本地等价实现树对应 `c969c6d7`，实验 worktree 从仅多统计脚本的 `c435c8cb` 建立。
- `rc4.rs` Git blob：`25895085e7c3e64752c0781b439cbba29e0184cd`。
- rustc `1.99.1 (58cf8f9c3 2026-10-13)`，LLVM `23.1.1`，x86_64，AMD EPYC 9V74。
- 独立 Rust 探针直接包含当前 `rc4.rs`，开启 `no_debug`；优化编译采用 `-C opt-level=3 -C lto=fat -C codegen-units=1`，无 PGO、无 `target-cpu=native`。CPU 2 串行运行。
- 候选仅把变量长度交错 KSA 内 `key[key_index]` 改为 `unsafe { *key.get_unchecked(key_index) }`，附范围证明。未将该候选写入生产文件。
- 首次短测与本代理的 ASan 测试有重叠，因此整次作废；下表来自 ASan 终止后独占 CPU 重新执行的完整配对，不混用早期数据。

## 汇编结果

导出独立包装函数，归一化局部标签后逐条比较优化汇编：

| 对比 | 结果 |
| --- | --- |
| `get_val` 安全索引 / `get_val_unchecked` | 完全相同：两条 `movzbl` 和 `retq`，无边界检查 |
| `peek_next_u8` / 全部 S-box 读取改 `get_unchecked` | 完全相同；条件分支是交换碰撞语义，不是边界检查 |
| 当前 unsafe PRGA / 对等安全索引 PRGA | 完全相同，无边界检查 |
| 变量长度 KSA 候选 | `update_interleaved` 汇编中的 `panic_bounds_check` 调用从 7 处降为 0 处 |

前三项没有理由再添加 `unsafe`。最后一项只能说明检查消失，不能直接说明实际程序更快。此处未为了清理已有代码而顺带替换当前 PRGA，也未改变其公开接口。

## 边界与别名审阅

- PRGA 的 `i/j` 虽是公开 `u32`，进入步骤时都截为 `u8`；加法为 `wrapping_add`。S-box 的任意内容仍是 `u8`，所以不依赖“必须是排列”才能保证 0..256 范围。交换先读再写，`i == j` 也合法，不创建重叠可变引用。
- 普通 KSA 在循环前拒绝空 key；`x` 来自 `0..256`，`j` 为 `u8`；`key_index` 从 0 开始，到 key 长度后立即归零。
- 同长交错 KSA 的唯一公开入口先检查所有 key 非空，再比较长度。9 字节展开的最后一组从 243 到 251，尾部明确执行 252..255。
- 前缀 KSA 仅保存最多 256 字节的前缀；成功匹配确保完整 key 至少同长；剩余索引同样回绕。
- 变量长度候选的唯一调用路径已拒绝空 key，各 lane 的 key_index 独立回绕；仅取消密钥读取检查，不改变索引、交换或随机流。
- `sort_list` 的排列索引也可做更复杂的安全证明，但还存在分配等成本；本次不盲目替换更多检查，不把它作为已测优化。

## 差分与地址检查

独立探针同时编译原始版和候选版：

- 现有 RC4 测试各 12 个，加上 2 个候选差分/非法输入测试，共 **26 tests**；debug 和优化版均通过。
- 新测试覆盖交错宽度 0..7、key 长度 1/2/8/9/10/255/256/257/511、round 0/1/2/3、任意高位公开 i/j、非排列 S-box。每组比较整个 S-box、i/j，再比较连续 513 字节和最终完整状态。
- 现有测试还覆盖全部 16 位小范围取余输入、0/1/255/256/65535/65536/0x00800000 边界、KSA 前缀、peek 碰撞、排除抽样及 golden RC4 状态。
- 空密钥/长度不匹配的前置检查保持原有 panic 行为；新增测试验证包含空 key 和数量不匹配会先 panic。
- nightly AddressSanitizer 的同一 26 tests 通过。LeakSanitizer 在该 ptrace 环境无法工作，故明确设置 `ASAN_OPTIONS=detect_leaks=0` 后验证地址安全；**未验证泄漏**。Miri 未安装，**未运行 Miri**。这些测试不等于对所有 UB 的数学证明。

## 微基准（不是 E2E）

每个变体每次执行 150,000 次双轮 KSA；每组 1 轮预热、7 轮配对，交替 A/B 顺序，所有对应 checksum 相同。吞吐变化为 `safe_time / candidate_time - 1`，不扣除控制组偏移。

| lane key 长度 | 吞吐中位变化 | MAD（百分点） | 更快配对 |
| --- | ---: | ---: | ---: |
| 8/9 | +1.59% | 1.84 | 6/7 |
| 8/9/10 | +4.43% | 1.78 | 6/7 |
| 8/9/10/11 | +4.63% | 4.13 | 5/7 |
| 255/256/257 | +0.91% | 4.53 | 4/7 |
| 9/9/9（同长路径控制） | +0.15% | 1.26 | 4/7 |

部分配对明显受调度噪声影响，尤其长 key 组有 -49.30% 离群值；因此不把这些结果包装成稳定收益，更不把它们与 FFA 或 namer-pf E2E 百分比相加。

`ScoreMatchGroups::set_round` 生成 `PROFILE_START + round * profile_count + offset`，其中 `PROFILE_START = 33554431`。本轮常规 n=13,000、最多 16 profiles 的名字均为 8 位，KSA key 长度均为 9，不经过候选分支；只有十进制位数跨界等少见场景才可能出现不同长度。为了几个罕见分支的微基准收益增加 unsafe 不符合本次 E2E 目标，故不保留候选，也没有对这个未保留候选另跑完整 E2E 或工作区测试。

数字与汇编对比摘要见 [`rc4-unchecked-2026-10-28/`](rc4-unchecked-2026-10-28/)。当前结论限定于这次编译器、目标平台与所审阅路径，不表示任何平台上的 unchecked 都无用。
