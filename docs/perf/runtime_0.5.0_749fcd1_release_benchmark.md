## 1. 环境与口径

- 机器：AMD Ryzen 7 5800X，8 核 16 逻辑处理器；
- 系统：Windows 10 专业版 22H2，build 19045，`x86_64-pc-windows-msvc`；
- Rust：`rustc 1.99.0-nightly (3d50c25bc 2026-07-16)`，LLVM 22.1.8；
- Cargo：`cargo 1.99.0-nightly (59800466c 2026-07-07)`；
- 构建：workspace `release` profile、fat LTO、`codegen-units = 1`、`no_debug`、默认 mimalloc；
- fixed30 每 case 13000 场：单线程 3 轮、自动线程 5 轮；
- win-rate 单线程 13000 场，每批 5 轮；CLI 时间精度为 1 ms；
- score 使用单线程 core batch 裸墙钟，排除构建、进程启动、输入读取和序列化；
- OpenBox CQP/CQD 包含自动调度、进度回调和内存探针，六档各 5 轮；
- 跨时段绝对值仅作方向参考。出现环境漂移时，发版判定使用同一会话中奇偶轮反转顺序的 0.4.3/0.5.0 交替 A/B 中位数。

输入与 0.4.3 发版基准相同，LF 归一化 SHA-256 也保持不变。

## 3. 为什么 OpenBox 使用同机 A/B

0.5.0 正式 OpenBox 六档相对早先存档的绝对值慢 1.82%～11.51%，CQP 双人 score 也慢约 3.6%。这组数字不能直接归因于代码：把精确的 0.4.3 `9d3a3b9` 二进制放到当前会话复跑，它自身也比自己的存档慢 4.64%～11.62%；双人 score 的旧二进制也慢 2.92%。

因此又执行了完整六档五轮交替 A/B。每个奇数轮按旧→新运行，每个偶数轮按新→旧运行。配对结果全部在 ±3% 内，且 700/700 或 1312/1312 matchup 全部完成。这同时保留了历史绝对数据，又避免把机器温度、后台负载或频率状态误判成代码回退。

## 8. 复测说明

主产品树已按 0.5.0 计划删除旧执行器及其辅助 benchmark binaries。fixed30 与 score 本轮使用只调用公开主 Runtime API 的临时外部 harness，构建后删除源码；原始 JSON 和当时二进制留在忽略的 `target/full_bench_0.5.0_749fcd1/`。这避免为了历史 A/B 把 V1 工具重新引入正式源码。

仍可直接复测的发布门禁和公开入口：

```powershell
python scripts/check_runtime_release.py --corpus
python scripts/verify_py_cli_api.py --release

target\release\tswn-cli.exe bench win-rate `
  -r "left@red`nright@blue" -n 13000 -s --perf

cargo build -p tswn_openbox --release --bin openbox_mem_probe
target\release\openbox_mem_probe.exe `
  --players docs\perf\cqp\sqp6000_first20.txt `
  --targets crates\tswn_openbox\assets\targets\target1.txt `
  --limit all --target-limit all --count 1000 --threads 0
```
