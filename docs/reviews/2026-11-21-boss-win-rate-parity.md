# 13 Boss 胜率逐场对齐

基线为[官网发布产物 `2ab0f562`](https://github.com/rinick/rinick.github.io/tree/2ab0f5620cc6d93c196d046834b983e5ae923e03/namerena)，文件校验值见 [Vite Boss 复查](2026-11-20-vite-boss-replay.md)。第一队为青雉、柯南、斑鸠、马里奥、史莱姆、索尼克、尤里；第二队为蚊、懒癌、一拳超人、新冠、灭霸、生命之轮。

- 胜率按原版 `rq=6` 对比：第 0 场无额外 seed，其余用 `seed:{33554431 + round}@!`。原版与 Rust 均为 183/1000。逐场胜方、可见批次数、每个可见批次的存活单位 HP／MP／行动点、RC4 游标和 256 字节置换表一致。比较不要求浏览器动画和文字占位参数逐字段一致。
- 批量复位以前跳过了 Boss 的初始行动点；史莱姆子体以前硬编码 `rq=4`。第 3 场在灭霸响指令史莱姆分裂后即可观察到后者：第一代子体的 MP 应为 25 而非 27。
- 反弹沿用原攻击的命中回调，不能按反弹者擅自替换；反弹传播要按实际施法者登记。多株感染的行动钩子按每株登记，而非复用历史记录的登记位置；魅惑解除后，后续同批状态按解除后的队伍结算。第 857 场第 58 个可见批次覆盖了魅惑解除后懒癌发作、生命之轮反击判定多消耗一个随机字节的情况。
- 回归测试固定原版 183 个胜场的编号，逐场断言而不是只比总胜率。

```powershell
cargo run -p tswn_core --bin tswn-cli -- bench win-rate -s -n 1000 -r 'aokiji@!+conan@!+ikaruga@!+mario@!+slime@!+sonic@!+yuri@!\nmosquito@!+lazy@!+saitama@!+covid@!+thanos@!+wheel@!'
```

## sqp5900 全量单挑

[sqp5900.txt](../../tests/sqp5900.txt) 共 3,684 个非空名字。每个名字分别单挑 13 个原版 Boss 和 `Rinick+属性修改器`，各跑 1,000 个固定种子，`rq=6`。逐场比较名字一方是否获胜，51,576,000 场全部一致。Rinick 的 3,684,000 场中，名字一方共胜 32,114 场。

Rust 额外测了 `testsubject@!` 和 `SAITAMA@!`，各 3,684,000 场。该原版构建没有这两个 Boss 的对应实现。全表共 58,944 个组合，胜率按名字一方计算。

- 狂暴强制普攻沿用空命中回调，保留受击触发的传播判定。
- 懒癌与暗杀按登记顺序覆盖行动提案。感染时立即重算属性，减速在疾走倍率算完后取整。
- 首次施加疾走会重算属性。Rinick 复活或分身后的面板会在这次重算中重新从属性值派生。
- 尤里对局的反例中，使魔自爆反弹触发提前死亡。原版在随后处理延迟自杀时仍调整行动游标。

回归测试 `sqp_duels_keep_vite_winners` 固定复现以上机制的种子。全量矩阵与工作区测试均通过，含 124 项冻结战斗语料。

## Rinick 胜率口径

Openbox 的 10% 档为 1,000 场。「不低估短号」控制名字系数所用的 `rq`，勾选时为 `rq=4`，取消勾选时为原版胜率模式的 `rq=6`。`openbox-cli cqp` 可用 `--keep-rq=false` 选择原版胜率口径。

| 名字 | `rq=4` 胜场 | `rq=6` 胜场 |
| --- | ---: | ---: |
| `虚蚓嬉申杆@Shabby_fish` | 43/1,000 | 51/1,000 |
| `Stupefy #mlMUWL12@Shabby_fish` | 45/1,000 | 46/1,000 |

两种口径的胜场数均用原版批处理与当前 CLI 复核。`rq=6` 的 2,000 场逐场胜负一致。
