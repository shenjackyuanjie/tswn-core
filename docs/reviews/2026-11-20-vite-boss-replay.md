## 验收结果

- 原有 649 场涵盖 13 个 Vite Boss、11,968 个可见批次；上一轮的 34 场规范战报差异归零。
- 额外 96 场涵盖队伍混合和多阵营联动、2,025 个可见批次；修复后，745 场在规范战报、可见分段、战斗状态、胜负及完整 RC4 上均无差异。另行复查的 dual307 对抗样本也通过逐批状态、战报和完整 RC4 检查。
- 普通基线对照 45/45 场通过：2,211 个主回合（含空回合）、2,256 个完整 RC4 检查点、2,180 个 CLI 回放帧、8,421 条更新均一致。普通致胜反弹用例的胜方行动点仍为 -305；两条原有特殊武器拒绝也保持。另以 Vite 直接抽查 12 场普通对局的 501 个可见批次，未发现差异。

## 验收口径

- 规范战报对照检查每个可见批次的模板、模板引用的角色、分数、发帧顺序；表情资源标签与空段折叠规范化。战斗对照检查胜方阵营、批数、逐批存活者 HP / 行动点 / MP。随机流对照直接比较初始及逐批 RC4 游标和完整 **256 字节**置换表，不以哈希代替。
- 普通对局使用从 `726ec2c5` 独立构建的真实基线，对照候选 CLI 字节输出、每个运行回合（含空批）的状态和 RC4 全表。覆盖组队、武器、使魔及复活、聚气、铁壁与普通致胜反弹；冻结语料不重生成。
- 独立复查通过实际 CLI、Python 与 WASM 的规范批量、逐帧、主动暂停续行及旧 WASM 兼容入口检查模板和延时。兼容投影保留旧数值格式；本轮没有把原版 HTML 资源、通用无施法者标记、原始伤害对象或浏览器等待策略全量复制为核心 API。
- 不能从公开样本推断任意输入逐帧全等。受控探针可在原版构造「新冠株 1 → 懒癌 → 新冠株 2」交错登记；当前 Rust 新冠多株共用一个状态条目，不能表述为已证明等价。复查在 1600 场定向生成对局未自然复现这类登记链，不为此扩大普通局调度改动。
