# CPU 搜索实验版

搜索入口 `CombatRuntime::run_search_round`，命令行 `clever-search`。默认战斗接口仍使用原版策略；Clever 展示页可显式启用搜索策略，其他默认战斗接口保持原版策略。

## 决策规则

- 保留强制行动、行动前后状态和正式结算流程。在完整回合起点克隆战场，不直接拼接伤害结果。
- 每个正熟练度主动技能独立抽取一次资格；保留原技能概率及武器特例，关闭原智慧低血阈值等战术偏好。MP 门槛仍为 8～23，最终选择技能时扣费。物理和可负担的魔法普攻也参与比较。
- 单体攻击与控制枚举全部合法敌人；治疗枚举受伤队友，加速枚举存活队友，苏生枚举未被消耗的常规友方尸体。目标按行动者的有效阵营判断。群攻覆盖全部首目标，后续采用低血量、高输出两种队列并去重，不穷举全部排列。武器特例保留原选择过程；Boss、cards、effective skill weights 暂退回原策略。
- 每个候选先用 2～3 个共同独立 seed 短续局（最多 8 个调度轮）筛选；保留总分第一，并为不同动作类别保留最多半数名额。默认最多 4 个入围候选均完成同一组 16 次采样，不再凭前 4 次结果提前淘汰。筛选试算另外计费，samples 不是所有候选试算次数的总上限。
- 位置评价包括绝对与相对 HP、输出、防御抗性、有效速度与行动条、MP、护盾、冰冻诅咒毒、蓄力聚气隐匿暗杀、保护关系、可复活尸体储备。魅惑期间按剩余步数将 75%～90% 资源价值归有效阵营，其余留在原阵营；这些权重是启发式，尚未拟合。
- 一半样本用原版续局；另一半在前三次真实可选动作机会做单层战术比较，空调度轮、强制行动和未接管的对手不消耗名额，其余仍用原版。主续局上限仍为 128 调度轮。局部比较遇到潜行起手时，另跟进最多 32 个调度轮，交由正式引擎结算背刺、打断或死亡后再评价，期间不枚举新动作、不递归搜索。单方验证的模拟对手始终走原版。模拟使用独立 seed，不能读取真实战斗未来随机序列。
- 终局奖励为己方胜 +1、负 -1；未终局使用半幅启发式值。返回 value 不是校准胜率；wins/completed/samples 按实际最终阶段试算单独记录。完整采样和局部延迟结算会增加计算量。
- 当前评价将其他队伍合并计入敌方资源，主要用于两队研究；多队博弈、完整状态估值和所有技能目标枚举仍待扩展。尚未证明相对原版有统计显著的胜率提升。

## 逐技能评价

普通 25 个主动技能、10 个被动技能及召唤物动作的目标、收益、代价与剩余状态口径见 [技能决策评价表](clever-skill-evaluation.md)。+武器（含死亡笔记）不纳入本次技能补齐；原有正式战斗兼容逻辑保留。

毒按总量与剩余跳数递推，灼烧结合可用火球/地裂威胁，诅咒按六位概率与后续受击放大评价；潜行残值考虑魔法攻击、目标抗性及打断，蓄力生命之轮允许比较仅夺取行动条的目标。即时收益仍由正式引擎结算，不能将状态残值理解为已证明的评分提升。

## SSH 服务器运行

需要 Rust 工具链和系统编译工具，在仓库根目录执行：

```bash
cargo build --release -p tswn_core --bin clever-search --features 'no_debug,mimalloc_alloc'
./target/release/clever-search --input roster.txt --matches 256 --workers 128 \
  --samples 16 --horizon 128 --shortlist 4 --seed 1 > search.jsonl
./target/release/clever-search --legacy --input roster.txt --matches 256 --workers 128 \
  --seed 1 > legacy.jsonl
```

输入沿用普通名字文本，空行分队；命令行用 seed 和对局编号派生显式战斗种子，忽略输入中的 seed 行。每行输出一场结果，线程完成顺序不固定，按 match 对齐。默认双方均搜索；可加 `--search-team 0` 或 `--search-team 1` 只接管指定运行时队伍，另一队使用原版。运行时队伍编号不保证等于输入队伍位置，严谨评测还需按 input_groups 映射并交换输入位置。legacy 运行双方均使用原策略。

先用 1/8/32/64/128 workers 测吞吐和内存，再选择服务器并发。128 核不意味着应在一个决策内部开 128 个线程；当前并行单位是独立对局，每个工作线程内部串行搜索，避免线程嵌套。

示例参数仅是起点，没有在远程机器测性能。先以 2 场、2 samples、16 horizon 冒烟，再增加预算。horizon 以引擎推进次数计，包含可能没有行动的调度轮，不等于角色出手次数。max-rounds 截断通过 truncated 标记，不能计为负场。

## 后续验收

使用单方搜索/单方原版的对照、交换队伍位置、独立名单和 seed 集，报告胜率区间、截断率、吞吐、内存与每次决策耗时。接入前端或训练网络前，需完成这一步。

## Clever 网页与发布来源

- 前端入口：https://kodu16.github.io/namerena/ 。默认选择原版策略，可在输入面板显式启用 Clever；strategy=search 分享链接保留 Clever。双方搜索预算为 16 samples、128 horizon、4 shortlist，模拟 seed 固定为 1；对照时输入相同的显式 seed 行。分享链接保留策略。
- 网页通过 WASM BattleSession.set_search 接入同一 run_search_round，每次只推进真实回合，试算不计入回放或回合上限。搜索耗时随阵容增长，尚未验证策略整体胜率优于原版。
- 发布源固定为本项目 KODU16/tswn-core-clever 的 main；仅在用户明确要求时同步 shenjackyuanjie/tswn-core，合并后保留 Clever 搜索与评分扩展。后续修改应从这里验证、提交并发布至 Clever main。
- KODU16/kodu16.github.io 的 Pages 工作流每 5 分钟检查 Clever main，对比线上 build.json，只在版本变化时重建，WASM 和前端取同一提交。GitHub 定时任务可能延迟；手动运行主页部署工作流可立即同步。

## 原版双队逐步胜率

右侧对局设置栏底部的“逐步胜率测算”默认关闭，仅适用于两支队伍，与 Clever 互斥。页面默认原版，显式选择 Clever 或 strategy=search 分享链接才启用搜索。战斗中首次开启测算会重新开始当前输入，以补齐所有步骤；关闭只隐藏面板，再开启复用当前缓存。

每个可见帧结束后，从完整 RuntimeRunner 克隆 10,000 场原版续局，保留 HP、MP、行动顺序、效果状态、尸体和召唤物，仅替换试算随机流。样本 seed 固定为 state-win-rate:样本序号，不读取正式战斗未来随机序列。每场最多 10,000 个调度回合，未决场单列并计入总场数。“100%”指完整采样进度，胜率为经验估计。

左下角列出双方全部输入名字、图标和队伍胜率，按运行队伍编号对应。每帧缓存只属于当前战斗；后退、前进和从头播放复用缓存，开始下一场即释放。单队或多队不试算、不展示。开启会增加每步等待时间，分批试算期间可取消或打开新对局。

胜率面板下方的蓝色折线按输入第一组统计，左上为第一组图标与 100%，左下为第二组图标与 0%。默认随回放显示最近 10 个已测步骤，下方滑块可浏览更早记录，“跟随回放”恢复自动跟随。悬停或键盘聚焦节点显示回合与双方精确百分比，点击或 Enter/空格调用现有 stepPlaybackTo 跳到该帧结束处并暂停。图表仅使用同一场的缓存，不发起胜率测算；新战斗释放图表状态。

## !test! 有限评分测试

```text
!test!

alpha
```

四种模式沿用参考站的 `!` 和重名输入约定；`!` 必须单独成行，放在 `!test!` 后、被测名字前：

| 模式 | 输入（`\n` 表示换行） | tswn 对应 |
| --- | --- | --- |
| 普通单挑 | `!test!\n\nalpha\nalpha` | pd，普通 profile，1 对 1 |
| 普通评分 | `!test!\n\nalpha` | pp，普通 profile，2 对 2 |
| 强化单挑 | `!test!\n!\n\nalpha\nalpha` | qd，强化 profile，1 对 1 |
| 强化评分 | `!test!\n!\n\nalpha` | qp，强化 profile，2 对 2 |

普通 profile 使用 `\u0002` 修饰符，强化 profile 使用 `!` 修饰符；只切换陪测 profile 的构造，不改写被测名字。单名评分由被测名字与一个 profile 组队，对战两个 profile；相同名字两行只保留一个被测实体，对战一个 profile。多名字队伍继续沿用现有评分分组规则。页面标题显示模式与出招策略。

输入面板的策略决定全部 10000 场 profile 对局的战斗方式：选择 Clever 时，双方均使用与回放一致的 run_search_round 和 16/128/4 预算；选择原版则双方原版。新增的“评分验证”复选框默认不勾选，只有勾选且选择 Clever 时，才让被测本体及其 profile 队友使用 Clever、对手使用原版。普通对局不受此框影响。只在累计 1000 场（10%）和 10000 场（100%）展示结果，随后永久停止该会话。Profile 名单、空战斗 seed 和 WIN_RATE_EVAL_RQ 沿用现有评分接口；旧 score() API 仍为原版评分。

技能／动作频率沿用参考站口径：被测本体产生的正 score、含 [0] 的真实消息次数，除以已完成场数再乘 100。不计 profile、召唤物、搜索试算及兼容层的 [s_dmg0] 伤害消息。这是每百局发生次数，不是每次出手的发动概率，可以超过 100%。Worker 支持立即取消正在计算的对局。

参考：https://github.com/namerena/namerena.github.io/blob/master/md5.js 的 V.eQ 与 lang/zh.json。本实现按需求设置固定上限，不继续进入参考站的扩大样本循环。

## 本机配对评分验收

```powershell
cargo build --release --offline -p tswn_core --bin clever-score-compare --features no_debug
./target/release/clever-score-compare --name alpha --name A@WgFlz3E --rounds 256 --workers 4
```

工具明确开启单方 Clever，对每个名字的 pp/pd/qp/qd 四种模式分别与全员原版比较；两次运行采用完全相同的 profile 顺序、空战斗 seed 和评分口径。默认每种模式 10000 场，可用 rounds 指定不超过 10000 的固定样本量。默认搜索预算与网页一致，不为评分降低强度。

早先两个名字、八项各 10000 场的结果见 [历史配对评分验证](clever-score-validation-2026-11-20.md)。后续 [铁壁与背刺延迟收益修复](clever-iron-backstab-fix.md) 将报告名字的强化单挑从旧 Clever 6952 提高到 7305，原版为 7101；仍不能据单个名字推断总体更优。工具可用 `--mode qd` 只运行强化单挑，也可重复指定模式。

每行 JSON 输出双方评分、万分制提升、配对差值的近似 95% 区间、Clever 独胜与原版独胜场数、精确双侧 McNemar p 值及截断数。positive_significant_unadjusted 只表示当前名字和模式未经多重比较校正的显著正提升；不能据此推断全名单提升。多个名字与模式应预先固定，并对检验数量校正。出现截断时不标记显著提升。
