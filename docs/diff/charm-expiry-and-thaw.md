- **14889–14908、15289–15300、15897–15908**：魅惑、疾走和迟缓的 `at` 都先减持续步数，并在归零时立刻调用 `this.K(null, b)`；三个 `K` 在重算前的流程只在元数据键名上不同：均在原地摘除更新钩子、删除元数据、摘除后行动钩子，然后重算。

## 单局实跑：先保留 Rust 的到期清理时序

用原始的 325 字节 CRLF 输入 [3v3v3-711d7e09df7b7da3.txt](../../crates/tswn_test/cases/runtime_stress/3v3v3-711d7e09df7b7da3.txt) 调用 JS `run_any`，仅观察 `Engine.O` 的可见战斗帧（不计单独的胜利通知）。JS 实测 **60 帧、7039 分、最终 RC4 (203,151)、胜者队伍 1**，与冻结值一致。Rust 的冻结基线由旧 Rust `CoreEngine` 生成，并非直接采自 JS。

- 第 41 帧，Goodbye 吞噬倒下的第227号命令。当帧原版依序运行新挂载的守护（优先级 10000）、蓄力、魅惑（后两项优先级为 Infinity）。守护仍按被魅惑队伍选中「你是个可敬的对手」，RC4 从 (215,83) 到 (228,39)。这之后才是该局唯一一次自然解除魅惑：`F()` 调用前 `rx` 已无魅惑，调用后 Goodbye 立即从「后勤、王鱼、你是个可敬的对手」所在的队伍切回原队伍。
- 干净 Rust 和仅修复自然解冻的 Rust 均匹配全部冻结摘要；本局没有自然解冻。若只把三种到期清理改为同步，第 41 帧的消息与分数不变，后置 RC4 却从 (228,39) 变成 (232,44)；下一帧从普攻王鱼且被回避变为潜行到王鱼身后，最终只有 56 帧、6351 分、RC4 (74,97)。
- 当前 Rust 的吞噬会按注册游标安排新启用的早段后行动技能（[effects.rs](../../crates/tswn_core/src/runtime/combat/effects.rs#L583-L614)）。保留现有到期延迟清除；在改为同步前，先对齐吞噬后守护与魅惑到期的相对顺序，再验证完整语料。

## 自然解冻：行动点累加前完整重算

- **18422–18430**：角色按当前速度掷出步数，逐项调用前置步进钩子 `fo`，最后才把返回的步数累加到行动点。行动点须严格大于 2048 才触发行动。
- **15421–15449**：冰冻的 `ar` 写入 `a.A = true`。自然解冻只在本步为正、剩余冰冻步数已非正且 `a + r.r.l >= 2048` 时发生；同步执行以下解除逻辑并使当前步数返回 0。

  ```js
  // IceState.fo 达到自然解除阈值：
  r.K(null, c)
  return 0
  // IceState.K：
  this.D()
  s = this.r
  s.r2.U(0, "ice")
  this.x.D()
  s.F()
  ```

  因此自然解冻提交的不仅是正在等待生效的疾走倍率，也包括重魅写入的新队伍和其余仍挂载的更新钩子。没有剩余魅惑时，重算结果是原始队伍；仍挂载魅惑时，结果是最新待生效的魅惑来源队伍。Rust 在调度层只能在冰冻摘除成功后对 `EntityRecord` 完整重算，再累计行动点。
