# tswn_core 0.5.2 更新说明（开发中）

> 0.5.2 尚未发布。本文件随 `tswn-cli 0.5.1` 历史评分差异的修复进度持续追加，
> 等全部差异处理完再整理正式发布内容。

## Merge 状态刷新

旧版 `Merge` 会先完成属性和技能合并，再统一调用一次 `update_states()`。
这次刷新除了应用新的衍生属性，也会把此前已经叠加、等待完整属性重算的
Haste 倍率提交为当前有效倍率。

主 Runtime 原先只在属性确实变化时刷新运行时属性。若吞噬只提升了技能等级，
状态刷新会被跳过，实体继续按旧 Haste 倍率积累行动点，随后产生行动顺序和
胜负偏差；属性和技能同时变化时，刷新又发生在技能合并之前，与旧版的统一
刷新时机不同。

修复后，属性合并先只更新模板衍生属性；技能固定槽合并完成后，只要属性或技能
任一发生变化，就统一刷新一次运行时属性。正式运行时没有新增调试输出，
`no_debug` 的编译期裁剪约定保持不变。

新增两层回归覆盖：一项最小测试验证纯技能 Merge 会把 Haste 的
`effective_faster` 从旧值刷新为新值；一项真实评分单局测试冻结
`琉音芽玲亚 #AIBSXOQHSK@无惨` 第 6539 局的旧版胜负结果。

该根因对应数据库中 5 条 `tswn-cli 0.5.1` 历史差异记录，修复后的精确单局
结果已与 Bun 一致。

## 铁壁打破后的残留 hook

旧版铁壁在承伤超过保护值时会立即执行 `Iron.K`：注销防御、行动后与属性更新
hook，移除铁壁状态，并当场刷新一次属性。

主 Runtime 原先只把铁壁的保护值和剩余步数置零，保留行动后条目直到该角色的
下一次行动。届时延迟清理还会额外刷新一次属性；若铁壁打破后、下一次行动前
重新叠加了 Haste，这次旧版不存在的刷新会让待生效倍率提前生效，改变行动顺序。

修复后，铁壁在打破帧内立即移除并刷新，不再留下零值 hook。真实评分第 6670 局
与另外 4 个唯一输入的首个差异局均恢复旧版胜负；按历史消息重复记录计共 9 条。

## 尾部空队名

旧版把 `name@` 中的空队名视为无队名，等价于 `name`。Rust 解析器此前保留
`Some("")`，导致后续以空 clan 参与 RC4、名字因子和属性构造，四项评分因此
出现大范围差异。

现在空队名统一归一化为 `None`，并增加解析与 score 等价回归。历史输入
`宗铭丸 #DCVIDQJX@` 的完整 10,000 局四项结果恢复为
`3031|2258|1602|405|7296`，与 Bun 一致。

## 冒号队名后缀

Bun 的 `parse_names` 会把 `name@team:metadata` 中带冒号的后缀当作无队名，常见
用途是随输入携带描述性元数据。Rust 原先只有 `id_name` 忽略了这类后缀，
`PlayerSpec` 却仍保留它作为 clan；同一个角色因此会走不同的 RC4、名字因子和
属性构造。

现在解析阶段直接把这类后缀归一化为无队名，属性和身份使用同一语义。真实输入
`荧屏上的梦想 NWKm7L_6@dream_on_screen qp:6070` 的完整 10,000 局四项评分已从
`3949|3661|2321|996|10927` 恢复为 `3994|4163|2182|1175|11514`，与当前 Bun 一致。

同时修复 score 的一个独立回退分支：固定 target 与动态 profile 使用同 clan 时，
会回退完整 roster 构造；该路径没有可回收的 score 专用缓冲，之前却强制要求回收
而 panic。现在正常完成回退构造，并有回归测试覆盖。

## 嵌套自定义幻影的延迟蓝图

带自定义 shadow overlay 的角色可以让首层幻影继续拥有 `Clone`、`Shadow` 等技能。
这类战斗召唤物不经过 root score profile 的初始化，原先也没有懒蓝图标记；它们
再次施放幻术时，Runtime 会读取空的 shadow blueprint slot 并 panic。

现在战斗召唤物会按自身的内部 `id_key_name` 延迟构造下一层蓝图。这里不能使用
战报显示的 `?N` 名：旧版 JS 会把 `?N` 仅用于显示，内部名仍保留 `?shadow` 或
`?summon`，名字属性也因此保持同一条构造路径。新增真实 score profile 回归，覆盖
自定义幻影 clone 后再次施放 shadow 的完整对局。

该修复先消除了崩溃；对应历史 case 的评分差异仍在后续排查，未计入本轮已对齐数。

## 调试探针

本轮使用的探针一并保留，便于以后复现 score 边界：

- `md5_fight_probe.js` 的第 6 个位置参数可传真实目标名，`--tick` 输出旧版逐 tick
  行动点、速度和 RC4；
- 忽略测试 `probe_score_outcomes_from_env` 支持 `TSWN_SCORE_PROBE_MAX_ROUNDS`，
  可在首个分歧附近提前停止；`TSWN_SCORE_PROBE_DUPLICATE=1` 可构造 Bun 的重复
  目标评分形状；
- `TSWN_PROBE_STEP=*` 跟踪全部 Runtime 调度实体；
- `TSWN_PROBE_REFRESH=<名字片段>` 在 pending Haste 被属性刷新提交时输出调用栈。
- `TSWN_PROBE_MINION_BLUEPRINT=1` 输出战斗召唤物延迟构造下一层蓝图的来源。

后两项正式运行时探针都位于 `#[cfg(not(feature = "no_debug"))]` 中，启用
`no_debug` 时不会编译对应环境变量读取、日志或调用栈分支。
