# tswn_core 0.5.1 更新说明

本轮继续收敛 `namer-pf` 与 Bun / `md5.js` 的历史评分差异，重点修复主 Runtime
在 score profile、状态刷新、保护重定向和召唤物延迟死亡链上的边界语义。

## namer-pf 正确性修复

- score profile 的数值角色不再按同长度名字共享 clone factor；每个 profile
  独立计算名字因子，并按旧版语义重建 clone 的技能等级和衍生属性。
- 对齐 Poison、Heal、Curse 等状态增删时的属性刷新时机，避免 pending Haste
  倍率被过早应用或遗漏。
- 召唤自爆经过 Protect 重定向时继续携带 Fire on-damage 回调，使火焰层数落到
  实际承伤者。
- Protect 的旧版重试候选继续包含 `alive=true`、但已经在延迟死亡链中变为
  `hp=0` 的召唤物，以保持 RNG 消耗顺序。
- owner 死亡清理联动召唤物时跳过上述 `hp=0` 的延迟死亡实体，由其自身死亡链
  完成移除；同时保持实体顺序、回合游标和消失消息顺序，不再提前删除或重复删除。

数据库中的 `tswn 0.5.0` 历史差异使用以下命令重新执行：

```powershell
python scripts\find_bun_tswn_namer_pf_mismatches.py `
  --tswn-version 0.5.0 `
  --retest --retest-only-diff `
  --retest-thread 8 --retest-timeout 60
```

结果为 44 条全部一致：`已一致 44`、`仍不一致 0`、`缺分数 0`、`错误 0`。

## 性能复测

性能对比使用 `docs/perf/runtime_0.5.0_749fcd1_release_benchmark.md` 记录的正式
基线提交 `749fcd1ddec2fb6544f24b15c1c579cb3285a476`。基线与本提交均使用同一套
当前工具链重新构建：

- `rustc 1.99.0-nightly (008fa22ce 2026-07-25)`；
- workspace `release` profile：fat LTO、`codegen-units = 1`；
- `no_debug`；
- 默认 mimalloc；
- 单线程 core `runtime_score`，排除构建、进程启动、输入读取和输出序列化；
- 每项先预热，再按旧→新 / 新→旧反转顺序交替执行 5 轮并取中位数。

正式普通评分 modifier（`\u0002`，对应 pp）结果如下。三组胜场与基线完全一致，
但 wall time 均有小幅回退：

| 输入 | 基线中位数 | 当前中位数 | 变化 | 胜场 |
| --- | ---: | ---: | ---: | ---: |
| mario，1 × 13000 | 0.4147961 s | 0.4248073 s | +2.4135% | 4171 |
| CQP 单人，20 × 1000 | 0.6563780 s | 0.6791103 s | +3.4633% | 14513 |
| CQP 双人，32 × 1000 | 0.9214338 s | 0.9508144 s | +3.1886% | 30295 |

附加的 `!` modifier（对应 qp）同口径结果为：mario `+2.6144%`、CQP 单人
`+3.5692%`、CQP 双人 `+1.1999%`。该组修复会增加少量 profile 初始化与边界
处理成本；本轮以正确性为第一优先级，性能回退如实保留，后续可单独采样优化。
