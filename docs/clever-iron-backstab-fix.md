# 铁壁与背刺延迟收益修复

针对名字 `跙坥咀诅阻珇伹伹怚@涵虚`，使用强化单挑 qd、单方 Clever 对原版的评分口径。双方 profile 序列、空战斗 seed、WIN_RATE_EVAL_RQ 均相同；固定 10000 场，搜索为 16 samples / 128 主续局调度轮 / 4 shortlist，独立搜索 seed=1。全部场次无截断。

## 结果

| 策略 | 强化单挑评分 |
| --- | ---: |
| 旧 Clever（e3facd9） | 6952 |
| 修复后的 Clever | 7305 |
| 全员原版 | 7101 |

修复后相对旧 Clever 提高 353 分，同一 profile 下独胜 1309 场、独负 956 场，精确双侧 McNemar p=1.2541e-13。相对全员原版提高 204 分，独胜 1979 场、独负 1775 场，p=0.00091990，配对差值近似 95% 区间为 +83.97～+324.03 分。

前 1000 场用于定位问题。将其余 9000 场单独汇总，修复后为 7286.67，旧 Clever 为 6963.33，原版为 7097.78；相对原版提高 188.89 分，p=0.0036342。这是对当前固定 profile 分布的案例验证，未证明全局最优或完整名字名单的普遍提升。

本体真实动作统计中，铁壁从 7525 次增至 8402 次，背刺从 7371 次增至 8030 次；不包含搜索试算。

## 定位与修复

1. 战术续局原来只在第 0、8、16 个调度轮探测，空轮、未接管的对手会浪费名额。现在按前三次真实可选动作机会计数，保留原版对手的完整行动路径。
2. 单层局部估值原来在潜行起手后立即停止，低估下一次强制背刺。现在对该起手最多跟进 32 个额外调度轮，让正式引擎处理背刺兑现、受击打断、目标失效或死亡，再比较结果；中间不递归搜索，也不读取真实战斗未来 RNG。
3. 四个样本就淘汰一半候选会放大偶然结果。现在全部入围动作跑满同一组 16 次采样。仅此一项在前 1000 场未改变总分，因此不能把主要改善归于该项。

| 累积改动 | 前 1000 场评分 | 完整 10000 场评分 |
| --- | ---: | ---: |
| 旧 Clever | 6850 | 6952 |
| 全部入围动作等预算 | 6850 | 未单独运行 |
| 再修复续局机会计数 | 7190 | 7210 |
| 再跟进潜行的强制结算 | 7470 | 7305 |

铁壁、潜行的资格与 MP 扣费规则保持引擎口径；修复由技能状态和实际行动驱动，生产代码不按名字设置策略。完整采样与局部延迟探测会增加单次决策计算量。局部延迟探测最多 32 轮，仍是有限近似。

## 验证

- 新增行为回归覆盖：晚于第 24 轮的己方决策仍能选出立即致胜动作、潜行的延迟背刺能得到正确选择、铁壁到背刺的无帧试算与正式捕获帧状态及 RNG 一致。
- 前两个行为用例分别在恢复旧轮次窗口、去掉延迟结算时失败，修复后通过。
- 核心 871 项单元测试、91 项 CLI 测试及适用集成测试通过；WASM 原生 12 项、前端 Node 61 项通过；nightly 格式检查及 diff 检查通过。
- 实际构建的 WASM 完成同一名字 10000 场评分，结果与 CPU 一致为 7305，完成后再次 step 不推进。
- 另用 alpha、A@WgFlz3E 的四模式各 1000 场作旁路检查；这八项小样本结果不作为总体提升的证明。

复现强化单挑：

```powershell
cargo build --release --offline -p tswn_core --bin clever-score-compare --features no_debug
./target/release/clever-score-compare --name '跙坥咀诅阻珇伹伹怚@涵虚' --mode qd --rounds 10000 --workers 1
```

网页仍需勾选评分验证才采用单方 Clever 对原版；默认不勾选时双方 Clever。
